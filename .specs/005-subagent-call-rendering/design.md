# Design: Subagent Call and Output Rendering

## Overview

`subagent_call` retains its default-shell `renderCall` spinner and expanded prompt. Its final `renderResult` performs cleanup and identity synchronization, returns an empty component for success so Agent Output is never nested in the tool execution box, and returns an indented one-line failure-reason body for tool-level failures so collapsed failures are never silent. `subagent_output` hides its default tool-call row with an empty `renderCall`, so only its `renderResult` Agent Output is visible.

`new`/`resume` always execute in background: the live row reads `Agent Call · <agent> · background · <new|resume>`, settles to the accepted `»` form once the queued acceptance returns, and settles to the literal lowercase ASCII `x` form (same metadata, `error` color, no inline error suffix) when the tool call itself fails before acceptance, with the sanitized one-line reason (error message, else code, else `Agent call failed.`, capped at 120 characters) rendered indented in the result region even when collapsed. The settled outcome is stored as renderer-local `state.failed` alongside `state.accepted`, so a later settled `renderCall`/host replay renders deterministically (`x` only from the `subagent_call` error envelope/`isError`; the child's later terminal status never flips Agent Call). Identification callbacks update only presentation metadata and never emit a partial `onUpdate`. `steer` is an immediate control operation rendered as `Agent Call · <agent> · steer` with no execution-mode label; only steer reports identification through `onUpdate`.

`src/runtime/agent-output.ts` owns the Agent Output projection, sanitization/caps, the shared `sanitizeReasonText` one-line 120-character helper (also used for call failure reasons), and the single shared Agent Output component, which renders only inside the `subagent_output` tool result region. Failure headings carry only glyph/title/metadata; every failure shows the indented reason body even when collapsed, and expanded failures preserve actual/partial output alongside the still-visible reason without duplicating byte-identical error text. No message renderer is registered and there is no entry renderer and no `turn_end` hook: with no foreground execution, the former foreground entry machinery (`AGENT_OUTPUT_ENTRY_TYPE`, `renderAgentOutputEntry`, `appendForegroundAgentOutputs`) and the obsolete completion custom-message renderer are removed as unreachable — queued acceptances and running acknowledgements carry no terminal output or error to report.

Background completion is a hidden custom signal carrying only session identity, terminal status, and a `subagent_output` fetch instruction. Durable result details and namespaced UI metadata preserve agent identity without changing serialized model-facing tool content.

Standalone HTML export does not invoke custom message renderers, so background custom messages export using the host's generic representation. Nested tool output is intentionally not reintroduced. Exporter limitation (verified, not fixable from this package): the host invokes `renderCall` before `renderResult` with a fresh state and no error context, so a settled failed Agent Call exports its header as `»` while the failure reason (and, interactively, the `x` glyph) is carried by the exported result section. Interactive replay is deterministic (`x` heading plus reason); export determinism covers the result section only.

## Decisions

- **D1:** Keep the default tool shell and static accepted Agent Call row.
- **D2:** Make final `renderResult` visually empty for success and an indented always-visible reason body for failure (both tools).
- **D3:** Remove foreground output entries entirely; completion is delivered only via the background follow-up message.
- **D4:** Use one Agent Output component for the `subagent_output` tool result renderer only.
- **D5:** Preserve the established background follow-up delivery path (`triggerTurn`, `followUp`, exactly-once); only the payload changes to the hidden minimal signal.
- **D6:** Use the literal lowercase ASCII `x` (never `✕`) in `error` color for both failure glyphs. Agent Output failure is `details.error !== undefined`, an `error` field/envelope on the raw details, or `status` in `{failed, aborted, stopped}`; headings never carry an inline error suffix. The always-visible reason prefers the safe error message, then the error code, then the terminal failure status, then a generic safe label (`Agent failed.` / `Agent call failed.`); it is one-line sanitized and capped at 120 characters.
